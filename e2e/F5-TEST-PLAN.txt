The dashboard observation fixture deliberately upserts 10 → 12 within the same
Bangkok day and then stores 20 on the next day. Its three stored rows comprise
two rows for Member A and one row for Member B; they are not three snapshots
for Member A. This follows the per-day observation uniqueness rule.

## System tests

These tests use the real frontend, authenticated backend and PostgreSQL.
Reporting fixtures insert only data owned by disposable test members and delete
those members on teardown. They do not intercept tracking API responses.
Database fixture setup does not claim to test live provider synchronization.

| Document cases | File and coverage |
| --- | --- |
| STC-F5-01-TC-01–TC-03 | `tests/system/tracking-sync.system.spec.ts`: actual OAuth/worker sync, duplicate request, page reopen and durable run restore (`@external`) |
| STC-F5-01-TC-04 | Same file: separately prepared revoked-token member, failed/partial run, reconnect message, old metrics retained (`@external`) |
| STC-F5-01-TC-05 | Same file: disconnected member, empty screen and no latest run |
| STC-F5-01-TC-06–TC-09 | `tests/system/tracking.system.spec.ts`: real public redirect endpoint, unchanged affiliate destination, repeat/nonqualifying/unknown-code requests |
| STC-F5-02-TC-01–TC-05 | Same file: latest totals, unavailable comments, seven detail rows/top five, connected empty state, two members with independent data |
| STC-F5-03-TC-01–TC-03 | Same file: ranking values, zero versus unavailable, unavailable sorted last, empty ranking |
| STC-F5-03-TC-04–TC-06 | Same file: 3/6 clicks, zero baseline, partial coverage |

The existing Vitest tests for `tracking/page.test.tsx` and
`useTrackingSync.test.tsx` additionally identify the STC behavior they isolate.
They supplement the system suite and do not replace it.

## Run

Backend, from `backend/`:

```powershell
.\venv\Scripts\python.exe -m pytest tests/unit/test_tracking_plan.py tests/unit/test_tracking.py tests/unit/test_tracking_sync_jobs.py tests/unit/test_tracking_adapter_errors.py -q -p no:cacheprovider
```

Frontend, from `frontend/`:

```powershell
npm test -- "src/app/(main)/tracking/page.test.tsx" src/hooks/useTrackingSync.test.tsx
```

System, from `e2e/`, with the frontend/backend running and `.env.test` pointing
to the same local database as the backend:

```powershell
npx playwright test tracking.system.spec.ts tracking-sync.system.spec.ts --project=system --grep-invert @external --workers=1
```

Use backend `REELCAST_TEST_MODE=true` for disposable registration fixtures.
The XLSX system assertion reads ZIP/XML using the backend Python environment;
set `TRACKING_TEST_PYTHON` if it is elsewhere.

For external sync, run a real adapter, Redis, sync worker and Beat. Prepare two
dedicated members with Published YouTube distributions and affiliate products:
one with valid credentials and existing metrics, one with revoked credentials
and previously stored metrics. Provide the following environment variables
locally, without committing credentials:

- `TRACKING_E2E_SUCCESS_EMAIL`, `TRACKING_E2E_SUCCESS_PASSWORD`
- `TRACKING_E2E_REVOKED_EMAIL`, `TRACKING_E2E_REVOKED_PASSWORD`

```powershell
npx playwright test tracking-sync.system.spec.ts --project=system --grep @external --workers=1
```

External cases skip explicitly when their account configuration is absent.
